System Architecture for One: Mapping My Personal Learning Environment

A mind map that diagrams my entire English learning infrastructure — the tools, the pipelines, the goals, and the gaps that only became visible once I drew the whole system out.

2026-10-04 • 5 min read • GA4-240202501-AA1-EV02
mind-map PLE architecture self-directed-learning GA4-EV02

A good software architect does not just know which components exist — they understand how data flows between them, where the bottlenecks are, and which services would take the whole system down if they failed. I applied that same thinking to my own English learning for this evidence: I mapped the entire Personal Learning Environment (PLE) as if it were a system diagram.

The result is evidence GA4-240202501-AA1-EV02 — a mind map built on the framework proposed by Kupchyk & Litvinchuk (2020), adapted to the specific context of a software development apprentice learning English as a second language.

The architecture — five main modules

The central node is the system itself: "My Personal Learning Environment (PLE) for English Learning & Work Application." Five modules branch from it. Here is what each one contains:

⚙️ learning strategies

  • Student-centred approach
  • Personalized learning path
  • Adapting content to my needs
  • Goal setting
  • Self-monitoring
  • Reflection on progress

🖥️ ICT tools

  • YouTube: programming in English
  • TED Talks about technology
  • Duolingo / Busuu
  • Anki — technical flashcards
  • Discord / Slack communities
  • Canva (infographics), Loom

📖 reading

  • API documentation
  • Stack Overflow
  • Software architecture articles

✍️ writing

  • Code comments in English
  • README files
  • Emails to clients / team

🎧 listening

  • Syntax.fm, The Changelog
  • YouTube coding interviews

🎙️ speaking

  • Daily stand-up meetings
  • Explaining solutions in English
  • Pair programming sessions

The module I underestimated: informal & autonomous learning

Every developer has shadow work — the reading, the experimenting, the Stack Overflow browsing that never shows up in a sprint but shapes every line you write. In my PLE, this is the Informal & Autonomous Learning module: learning while commuting, a vocabulary notebook, following English-speaking developers on Twitter/X, joining coding challenges in English.

One of its sub-nodes is "personal blog in English." That node is this blog. I mapped it before I built it — which means my PLE predicted its own next feature.

"A PLE is not the tools you have installed. It is the decisions you make about how, when, and why you learn — documented honestly enough to see the gaps."

What the diagram revealed: a speaking bottleneck

When I drew all five modules, I could see something I could not feel day to day: my reading, listening, and writing pipelines were active and well-connected. My speaking pipeline was almost empty. No regular practice, no feedback loop, no output. In system terms: a service with no consumers. Data comes in, nothing goes out.

Why architecture diagrams improve learning

Software teams draw architecture diagrams not to document what exists but to think more clearly about what should change. The same is true for a PLE. Making this mind map did not summarize my learning — it diagnosed it. It was the most useful fifteen minutes I have spent on English this year, because it turned a vague feeling ("I should practice more") into a specific problem ("speaking has no pipeline") with a specific fix (evidence 03, spoken self-introduction).

Kupchyk & Litvinchuk (2020) argue that PLEs built around ICT tools and metacognitive strategies produce more durable learning than traditional instruction. I would add one condition: the map only works if you draw it honestly. An architecture diagram that hides the broken services is not a map — it is a press release.
